# O3 — MenuManager [Core]

Source: upstream `NickFox007/MenuManagerCS2` v1.4.1, commit `5d2892aafdf80c3b6901e7112eb13f2d62cf05c3`. The installed #7 baseline DLL has SHA256 `18e435e70a259241ac679ebeec8701952c89a454f0e61cded14cd3c41dd6bbfc`. Its exact source-to-binary build provenance is provisional; the module version and upstream revision alone do not prove a binary match.

The patch removes per-tick button-mask string formatting and reuses rendered button-menu HTML until an output input changes. It checks title, visible option identity/text/disabled, count, page/selection, line count and localized strings. `PrintToCenterHtml` remains every tick. It also avoids displaying/removing a replaced menu after a selection/back callback and restores movement only on the original valid pawn. Public `IMenuApi`, shared assemblies and config format are unchanged.

Build: `dotnet build MenuManagerCore/MenuManagerCore.csproj -c Release --no-restore`. The unchanged upstream solution baseline built with 37 existing warnings and no errors; the candidate core builds with 27 warnings and no errors. Source targets .NET 8 and references CounterStrikeSharp.API 1.0.305. Test server #7 runs CounterStrikeSharp 1.0.378. No runtime or shared API was upgraded.

Behavior and synthetic renderer check: `dotnet run --project tests/O3/O3.csproj -c Release`. Seventeen checks pass for held/combined buttons, direct content mutations, selection, line count, localization, empty/reordered options and pawn replacement. The harness links the production `PlayerInfo.cs`, supplies managed stubs and compares rendered HTML with the original renderer. It does not measure native send or full game ticks. In one warmed run of 10,000 iterations, 32 open menus took 88.69 ms/778,240,040 allocated bytes in original rendering versus 27.77 ms/0 bytes in the cached repeated-render path. Results vary by run and are synthetic.
